# AI-DDD標準規約

## 1. はじめに：AI-DDDの基本理念と目的

現代のソフトウェア開発において、生成AIの活用はもはや「補助」ではなく「前提」です。本規約が定義するAI-Native Document Driven Development（AI-DDD）は、AIと人間が共生する環境下でシステムの整合性を極限まで高めるための戦略的フレームワークです。

### 理念の定義: ドキュメントを正（Source of Truth）とする

AI-DDDの核心は、ドキュメントが正（Source of Truth）であり、コードはその副産物に過ぎないという逆転の発想です。従来の開発ではドキュメントは事後の記録でしたが、本手法ではドキュメントがAIを駆動させる燃料となります。

### 組織的メリット

* 認識の不一致を根絶する
* 属人化を徹底排除する
* AI実装精度を最大化する

### 成果物の位置づけ

ドキュメントは静的な報告書ではありません。それはAIエージェントに次のアクションを指示し、プロジェクトの状態を即座に復元するための「開発を動かすエンジン」です。

## 2. 開発インフラと技術スタックの標準化

AIが自律的に動作し、環境依存によるエラーを最小化するためには、予測可能なインフラ構成が不可欠です。

### 標準環境の定義

開発は、Windows Subsystem for Linux (WSL2) 内の `~/projects/[project-name]` を起点とします。ホストOSとの差異を排除し、AIエージェントがファイル操作やシェル実行を確実に行える環境を強制します。

### 技術スタックの指定

* Backend: Laravel 12 (PHP 8.3+)
* Database: MySQL 8.4
* Frontend: Vue.js (Vite)
* Infrastructure: Docker / docker-compose

### AIエージェントの役割分担

* NotebookLM: 非構造化データの蒸留と資料生成
* Codex (VS Code): 仕様審議と論理構築
* Claude Code: Dockerコンテナ内での自律実装とテスト

## 3. AI-DDD 4フェーズ・プロセス・ガイドライン

### 3.1 抽出フェーズ（Extraction）

録音データやメモを、AIが理解可能な構造化データへ変換します。成果物は、背景や目的を保持した要件定義です。

### 3.2 審議フェーズ（Critical Design）

AIにドキュメントを攻撃させ、論理の穴を塞ぎます。データが空の場合やエッジケースを明示することで、ドキュメントは実装可能な仕様へと昇華します。

### 3.3 設計・タスク分解フェーズ（Design & Orchestration）

確定した要件を設計図へ落とし込みます。DBマイグレーション案、API定義、Vueコンポーネント構成図を生成し、AC付きのIssueへ分解します。

### 3.4 実装・検証フェーズ（Implementation & Testing）

Claude CodeがDockerコンテナ内でコーディングし、Unitテストを自律実行します。テスト通過がコミットの絶対条件です。

## 4. AIをチームメンバーとして活用するための行動規範

### 「状況把握」の定型化

VS Code起動時、必ず「今の状況を教えて」というプロンプトから開始します。AIは優先順位を持って情報をスキャンし、即座にコンテキストを同期します。

### コンテキスト維持の義務

AIの記憶力は、リポジトリ内の最新ドキュメントに依存します。README.mdおよび `docs/` 配下を常に最新化することは絶対義務です。

### 人間による最終検閲

AIの出力に対する論理チェックは人間の責任です。特にセキュリティ、パフォーマンス、ビジネスロジックの核心については最終ゲートキーパーが必要です。

## 5. 知見の昇華と資産管理（Documentation Assets）

### ドキュメント階層の定義

* `docs/requirements/architecture.md`
* `docs/requirements/db.md`
* `docs/requirements/api.md`
* `docs/requirements/decisions/`
* `docs/progress-status.md`

### NotebookLMへの再投入プロセス

マイルストーン到達時に、 `docs/` 配下の全ドキュメントを再度NotebookLMへインポートします。これにより、技術データがプレゼン資料や開発白書へと変換されます。

### 規約の締めくくり

AI-DDDの継続運用は、ドキュメントを負債から資産へ変えます。この規約を遵守することで、組織はAIと共に成長し続ける「学習する組織」へ進化できます。
